# WILKREY® — Digital Studio

Статический сайт на HTML, CSS и JavaScript. Сборка для локального просмотра не нужна. Для публикации см. раздел «Публикация».

## Структура

```
wilkrey/
├── index.html              # разметка, SEO, Open Graph, Twitter Cards, JSON-LD, favicon
├── robots.txt              # правила для поисковых роботов, ссылка на sitemap
├── sitemap.xml             # карта сайта (одна страница)
├── assets/
│   ├── styles.css          # дизайн-система, композиция, анимации, адаптивность, reduced-motion
│   ├── script.js           # шапка, меню, reveal, превью кейсов, курсор, форма заказа (Web3Forms)
│   ├── logo-mark.webp      # логотип (WebP, с прозрачностью)
│   └── og-image.png        # превью для соцсетей, 1200×630
├── scripts/
│   └── build-publish.sh    # сборка dist/ по белому списку файлов (единственный источник публикации)
├── docs/
│   └── PUBLISH-CHECKLIST.md  # чек-лист перед публикацией
├── deploy/                 # старая копия сайта (русская версия от 3 ноября), не используется, не публикуется
├── .gitignore
└── README.md
```

`deploy/` не подключён ни к `index.html`, ни к `styles.css`, ни к `script.js`, ни к скрипту сборки. Это архив предыдущей версии. Его удаление — отдельное решение владельца; сборка и публикация от него не зависят.

## Запуск локально

Откройте папку в VS Code и запустите **Live Server** («Go Live»). Либо откройте `index.html` в браузере напрямую: все пути относительные, сервер не нужен.

## Публикация

### Что публикуется

Только файлы из белого списка `PUBLIC_FILES` в `scripts/build-publish.sh`:

- `index.html`
- `assets/styles.css`, `assets/script.js`
- `assets/logo-mark.webp`, `assets/og-image.png`
- `robots.txt`, `sitemap.xml`

Новый публичный файл добавляется в `PUBLIC_FILES`. Без этого он в `dist/` не попадёт, и скрипт сборки упадёт, если файл не найден.

### Что не публикуется

`README.md`, `docs/`, `deploy/`, `scripts/`, `.git/`, `.gitignore`, `.wrangler/`, скриншоты и любые временные файлы. Скрипт сборки копирует только белый список, поэтому эти папки в `dist/` не попадают.

### Как получить production-сборку

```bash
bash scripts/build-publish.sh
```

Скрипт удаляет старый `dist/`, копирует файлы из белого списка и проверяет:
- содержимое `dist/` совпадает с белым списком (ничего лишнего);
- все `href`/`src` в `index.html` и все `url()` в CSS указывают на существующие файлы;
- все абсолютные ссылки `https://wilkrey.pages.dev/...` в `index.html` и `sitemap.xml` ведут на существующие файлы.

При ошибке скрипт завершается с ненулевым кодом. Исходники он не меняет.

### Cloudflare Pages

Два способа; оба публикуют только `dist/`.

**A. Подключение Git-репозитория (рекомендуется).** `dist/` в `.gitignore`, поэтому сборку выполняет сама платформа:

| Параметр | Значение |
|---|---|
| Framework preset | None |
| Build command | `bash scripts/build-publish.sh` |
| Build output directory | `dist` |
| Root directory | пусто (корень репозитория) |
| Production branch | `main` |
| Environment variables | не требуются |

**B. Загрузка вручную** (выполнять только после отдельного разрешения владельца):

```bash
bash scripts/build-publish.sh && npx wrangler pages deploy dist --project-name=wilkrey
```

Не используйте `wrangler pages deploy .`: эта команда загрузит всю папку, включая `deploy/`, `.git` и служебные файлы.

### Настройки домена (Cloudflare, после подключения домена)

- Speed → Optimization: **Rocket Loader выключить**. Он переписывает `<script>` и может изменить порядок выполнения inline-скрипта, который ставит класс `js`, и отложенного `script.js`.
- SSL/TLS: режим «Full (strict)», редирект HTTP → HTTPS включить.

### Поведение 404 и путей

- Сайт состоит из одной страницы. Неизвестные пути получают стандартную страницу 404 Cloudflare Pages. Собственный `404.html` не добавлен: это решение по дизайну, а не техническая необходимость.
- Все ссылки на ресурсы относительные (`assets/...`), поэтому сайт работает от корня домена и при открытии из любой папки. Абсолютными заданы только `canonical`, `og:url`, `og:image`, `twitter:image`, JSON-LD и `sitemap.xml`. Они указывают на `https://wilkrey.pages.dev/`. При смене домена их нужно обновить.

## Перед публикацией

- **Форма заказа.** Access key Web3Forms задан в скрытом поле `access_key` в `index.html`. Если ключ удалён или стоит заглушка, форма показывает «Форма ще не активна» и не отправляет запрос. Реальная отправка заявки в рабочем окружении ещё не проверялась: проверяется отдельно после разрешения владельца.
- Проверьте `og:url`, `canonical`, JSON-LD и `sitemap.xml`, если домен отличается от `wilkrey.pages.dev`.
- Превью кейсов загружают живые демо с `wilkrey.github.io`. Если сайт демо недоступен, в рамке будет пусто, а ссылка «View concept» продолжит работать.
- Полный список действий — в `docs/PUBLISH-CHECKLIST.md`.

## Формы без JavaScript

Форма заказа работает только с JavaScript. Без него браузер отправит данные напрямую на `api.web3forms.com`, и посетитель увидит ответ сервиса, а не страницу сайта. Сообщение об успехе в этом случае на сайте не показывается.

## Заметки

- Превью кейсов — это живые демо-страницы в уменьшенном виде, а не статические скриншоты. Загружаются они только при приближении к экрану.
- 3D-объект в hero построен на CSS (`transform-style: preserve-3d`), без WebGL и внешних библиотек.
- Анимации отключаются при `prefers-reduced-motion: reduce`.
- Шрифты подключаются из Google Fonts. Решение о самостоятельном хостинге шрифтов не принято.
